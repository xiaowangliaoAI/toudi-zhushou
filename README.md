## 「我投的不是招聘岗，能用吗？」——能用

**这套东西不是「招聘岗专用工具」。** 它分两层，只有一层跟岗位有关：

| 层 | 跟岗位有关吗 | 说明 |
|---|---|---|
| **执行层** —— 抓页面文本、筛选换批、核对送达、风控边界、坐标校准、驱动脚本 | ❌ **完全无关** | 平台就那几个，谁投都一样 |
| **判断层 · 骨架** —— 硬门槛一票否决 → 岗位实质 → 高/中/低三档 | ❌ **无关** | 换什么岗位都是这三步 |
| **判断层 · 内容** —— 哪些算硬门槛、哪些职责算「实质不对」 | ✅ **有关** | **必须换成你自己的岗位** |
| **招呼语素材库** | ✅ **有关** | 本来就得拿你自己的简历去拆 |

### 文件里为什么满屏都是「招聘」

因为那是我自己跑通全流程时投的岗位，**拿它当一份「已填好的样例」最能说明问题**。
**样例是给你照格式改的，不是限制你只能投招聘岗。**

### 换成你自己的岗位，只要三步

1. 打开 [`references/matching-rubric.md`](./references/matching-rubric.md)，
   把「硬门槛」表里的条目换成你那一行的（证书 / 语言 / 学历 / 年限 / 特定行业背景）。
2. 把「岗位实质」那几条换成你这行的「挂羊头卖狗肉」形态
   （挂着「运营」实则纯客服、挂着「设计」实则素材搬运、挂着「管培生」实则地推……）。
3. [`references/greeting-playbook.md`](./references/greeting-playbook.md) 的素材库，按你自己的简历重建一遍。

**执行层一个字都不用改。**

> ⚠️ **一句实话：这套东西给你的是骨架和流程，判断的肉得你自己长。**
> 我那份判据写得细，是因为我恰好在那个行业里。
> 你换成你的行业，那份细度得由你自己的行业经验来补 —— **骨架不会替你懂你的行业。**
> 这也是为什么它值钱的部分不是脚本，是那套「先卡硬门槛、再看岗位实质、最后才分档」的顺序。

## 快速上手

1. **建素材库**：把自己的简历拆成 6–8 段经历 + 可量化成绩，按
   [`references/greeting-playbook.md`](./references/greeting-playbook.md) 的模板落盘。
   ⚠️ 只写简历里真实存在的，不许推断、不许美化。
2. **填配置**：`cp assets/config.example.json assets/config.json`，替换掉所有 `<必须替换>`。
3. **小样实测**：先只投 **3–5 个**，确认「按钮流程 + 送达可见」都通，再考虑放量。
4. **隐私自检**（如果你要把它分享给别人）：
   ```bash
   bash scripts/pii_scan.sh .
   ```

## 时效性：工具会过期

> **最后验证日期：2026-09-18。**
> 本工具基于 **2026 年 9 月**的页面结构、风控行为与平台规则编写。

**它必然会过期**，因为有两个依赖会在你无法控制的情况下变化：

| 依赖 | 谁改 | 坏成什么样 |
|---|---|---|
| 页面结构（DOM / 布局 / 按钮位置 / 颜色） | 平台前端改版 | 定位失效 —— 点空、扫不到卡片 |
| 风控策略与平台规则 | 平台 | 原本不弹验证码的通道开始弹；规则里写的判据不再成立 |
| 招聘市场的话术与红线 | 市场 | 判定规则逐渐偏离实际 |

**所以：发布越久，越不保证有效。**

### 怎么判断它已经过期

| 症状 | 说明 |
|---|---|
| `locate.py button` 找不到按钮，或 `cards` 扫不出卡片 | 页面结构变了（大概率改版） |
| 原来能用的坐标全部点空 | 同上，或窗口尺寸 / 缩放变了 |
| 小样实测就弹验证码 | 风控策略变了 |
| JD 里大量出现规则没覆盖的新形态 | 判定规则该更新了 |

### 过期了怎么办

1. **先停。** 不要硬跑 —— 用失效的脚本反复试探，只会更快把账号送进风控。
2. **重新校准**：按 [`SKILL.md`](./SKILL.md) 的「校准」一节重跑 `locate.py`。
3. **更新规则**：改 `references/matching-rubric.md`，**不要改脚本**。
4. **改不动就别用**，回手动投递。

## 已知未验证项（诚实清单）

这些**没有在真实环境端到端验证过**，别当成熟功能：

1. **路线 A 是否被平台风控拦截** —— 本机实测 CDP 通道会触发「安全验证」选图验证码；
   `--user-data-dir` 独立 profile 是否同样被拦，**未验证**。
2. **Windows 后端** —— `scripts/uidrv.py` 的 Windows 分支按 Win32 API 规范编写，
   **未在真实 Windows 机器上跑过**。首次请先用无害动作（移鼠标、截屏）验证。
3. **混合 DPI / 多屏** —— 只在单屏 Retina（2x）与单屏 100% 缩放下考虑过。
4. **站点改版** —— `locate.py` 的颜色阈值与卡片扫描参数需重新调。
