# 跨平台可行性 & 分享前检查清单

> 这份文件回答：**这套东西换到别人的电脑上，能不能跑起来？哪些要换？**

## 一、结论速览

| 组成部分 | macOS | Windows | 说明 |
|---|---|---|---|
| 判断层（匹配规则/红线/话术） | ✅ | ✅ | 纯文本规则，直接可用 |
| 采集层（抓页面文本/换批/计数核对） | ✅ | ✅ | 只是键盘快捷键差异：`Cmd` ↔ `Ctrl` |
| 驱动层 · 路线 A（agent-browser CLI） | ✅ | ✅ | Rust/Node 实现，两端同一套命令 |
| 驱动层 · 路线 B（系统级合成输入） | ✅ CoreGraphics | ✅ SendInput | **两套实现**，已封装在 `uidrv.py` |
| 浏览器登录态 | ⚠️ | ⚠️ | **不能跨机器搬**，接收方需自己登录一次 |
| 坐标常量 | ❌ | ❌ | **必须现场校准** |
| 本机路径（venv / profile / 截图目录） | ❌ | ❌ | 必须改成配置项 |

**一句话**：规则和流程 100% 可用；驱动代码要按平台换；坐标和登录态必须在新机器上重建。

## 二、依赖清单（接收方要准备什么）

| 依赖 | 用途 | 必需性 |
|---|---|---|
| Python 3.9+ | 跑 `uidrv.py` / `locate.py` | 必需 |
| Pillow（`pip install Pillow`） | 截图像素定位 | 路线 B 必需 |
| 浏览器（Chrome/Edge） | 目标站点 | 必需 |
| `agent-browser` CLI | 路线 A 驱动 | 路线 A 必需 |
| 系统辅助功能权限 | 路线 B 发送合成输入 | 路线 B 必需 |
| 一份自己的简历 | 判断层输入 | 必需 |
| 目标站账号（已登录） | 投递 | 必需，且**必须本人登录** |

## 三、权限与系统设置差异

### macOS

- 「系统设置 → 隐私与安全性 → **辅助功能**」→ 把**调用方 App**（不是 Python，是启动脚本的那个应用，例如 WorkBuddy 本体）加入并勾选。
- 自检：`python -c "import ctypes;print(ctypes.cdll.LoadLibrary('/System/Library/Frameworks/ApplicationServices.framework/ApplicationServices').AXIsProcessTrusted())"` 返回 `1` 才可用。
- **屏幕录制权限**（用于 `screencapture`）通常首次调用会弹窗，允许即可。
- 若报 `-10004 权限违例`：说明调用方 App 的 `Info.plist` 缺 `NSAppleEventsUsageDescription`，**AppleEvents 被静默拒绝且无法手动开启** → 走路线 B，或换一个调用方。
- Retina 屏：截图是物理像素，逻辑点 = 像素 ÷ 2。

### Windows

- 一般**不需要**额外权限（同一用户会话下的 `SendInput` 即可）。若目标程序以管理员身份运行，驱动脚本也必须以管理员身份运行，否则输入会被 UIPI 丢弃。
- **必须处理 DPI 缩放**：125%/150% 缩放下若不声明 DPI 感知，坐标会系统性偏移。`uidrv.py` 启动时已调用 `SetProcessDpiAwareness`；若自行编写，务必保留这一步。
- 截图：`ImageGrab.grab(all_screens=True)` 取物理像素；多屏时注意虚拟桌面坐标（左屏可能为负）。
- 中文输入：不要用逐字符模拟，**统一走剪贴板 + `Ctrl+V`**（见下）。

## 四、剪贴板粘贴的跨平台写法（中文最容易踩的坑）

| 平台 | 写入剪贴板 | 粘贴 |
|---|---|---|
| macOS | `pbcopy`（stdin 传 UTF-8） | `Cmd+V` |
| Windows | PowerShell：`Set-Clipboard -Value ([IO.File]::ReadAllText('x.txt',[Text.Encoding]::UTF8))` | `Ctrl+V` |

`echo xxx | clip` 在 Windows 上会因控制台代码页丢中文，**不要用**。

## 五、明确不可复用（分享时要从包里剔除）

- ❌ 任何写死的坐标常量（只写「怎么定位」，不写「坐标是多少」）
- ❌ 本机的 Python venv / 脚本绝对路径（换成配置项或相对路径）
- ❌ 浏览器 profile 目录（含 Cookie/登录态）
- ❌ 发送方的简历全文、真实姓名、手机号
- ❌ 发送方的账号、会话记录、已投清单（属于个人数据）
- ❌ 本机窗口布局假定（浏览器必须在固定位置/尺寸——改成运行时校准）

## 六、分享前检查清单

给对方之前，逐项确认：

**法律与许可**
- [ ] `LICENSE` 已随包提供，且已填上著作权人署名（别留 `<填入...>` 占位）
- [ ] `DISCLAIMER.md` 已随包提供
- [ ] 已跑 `bash scripts/pii_scan.sh .`，输出为 ✅ 干净
- [ ] 包内**没有** `assets/pii_patterns.txt`（那是本机专属的个人关键词清单）

**内容与前提**
- [ ] 简历已换成**占位符或对方自己的**，包内无个人隐私字段
- [ ] 所有绝对路径已改为 `assets/config.json` 配置项，且带示例默认值
- [ ] 坐标全部走 `locate.py` 现场校准，包里没有硬编码坐标
- [ ] `references/portability.md` 已随包提供（对方需要知道前提）
- [ ] 明确写出**平台的已知限制与未验证项**，不夸大
- [ ] 有节流与人工确认机制，不是无人值守群发
- [ ] 提示了平台规则与账号风险（见 `compliance.md`）
- [ ] 首次运行引导对方**只投 3–5 个**做小样实测

> ⚠️ **最后一关**：声明和许可能减少「被滥用」的连带责任，但**不能消除平台协议风险本身**。
> 如果你打算**公开大规模发布**或**自己商业化**，先找律师看一遍，别拿这份声明当挡箭牌。

## 七、已知未验证项（诚实清单）

这些**没有在真实环境里端到端验证过**，分享时须如实标注，别当成熟功能：

1. **路线 A 是否被目标站风控拦截**：本机实测 CDP 通道会触发「安全验证」选图验证码；`--user-data-dir` 独立 profile / `--cdp` 挂载是否同样被拦，**未验证**。必须在目标账号上小样实测。
2. **Windows 后端**：`uidrv.py` 的 Windows 分支按 Win32 API 规范编写，**未在真实 Windows 机器上跑过**。首次使用请先用无害动作（移动鼠标、截屏）验证，再进入实际投递。
3. **多屏 / 高 DPI 组合**：仅在单屏 Retina（2x）与单屏 100% 缩放的设计下考虑过，混合 DPI 场景未验证。
4. **站点的 DOM/布局变更**：目标站改版后，`locate.py` 的颜色阈值与卡片扫描参数需要重新调。

## 八、推荐的分发形态

**不要分发「点击脚本」，要分发「工作流 + 规则」**：

- 主体是 `SKILL.md` + `references/`（方法论，跨平台稳定），脚本作为附件。
- 路线 A 优先：改动小、跨平台、无坐标依赖。只有 A 被拦时才启用 B。
- 明确告诉对方：**这是需要本人在场、分批确认的辅助工具，不是挂机跑量的机器。**
