# 风控、节流、合规与账号风险边界

> 这份文件是**刹车**。整套工具能不能长久用，取决于这一页有没有被认真执行。
> 分享给别人时，这一份**必须一起给**，而且要放在显眼位置。

## 一、先明确它不是什么

**它不是挂机跑量的机器。**

- ❌ 不做无人值守的批量群发
- ❌ 不做超量放量（几百上千）
- ❌ 不绕过平台的验证码/风控
- ❌ 不代替用户做沟通、不代替用户回复消息

**它是**：一个**需要本人在场、分批确认**的辅助工具——把「读 JD 判匹配」这段最费脑子的活自动化，把「点一下」这段最费手的活自动化。

## 二、已知会触发风控的通道（实测）

| 通道 | 实测结果 | 建议 |
|---|---|---|
| CDP 远程调试（`--remote-debugging-port`）挂载 | ⚠️ **会触发「安全验证」选图验证码** | 不推荐直连；如要用，先小样实测 |
| `--user-data-dir` 独立 profile | ❓ 未验证 | 小样实测后再放量 |
| 合成鼠标/键盘（系统级输入） | ✅ 未触发（对网页等同真人） | 推荐兜底路线 |

> **任何自动化通道都可能被平台识别。** 一旦出现验证码，说明通道已被标记，**立即停止并换路线**，不要反复重试——反复重试是最容易让账号进黑名单的行为。

## 三、节流参数（起始建议值，写进 config）

| 参数 | 建议值 | 理由 |
|---|---|---|
| `sample_size_first` | **3–5** | 首次必须先小样，确认全链路通 |
| `batch_size` | **≤ 10** | 一批做完停下来核对一次 |
| `pause_between_actions` | **1.5–3 秒** | 动作之间留间隔，不要连点 |
| `pause_between_batches` | **≥ 60 秒** | 批与批之间明显停顿 |
| `max_per_session` | **建议 ≤ 50** | 单次会话不要超量 |
| `stop_on_captcha` | **true** | 一旦弹验证码立即停止 |

**变通手法**：与其硬滚列表（会触发节流），不如**改筛选条件换一批**——换批是平台认可的正常操作，不是异常行为。

## 四、账号风险边界（谁承担风险，要讲清楚）

1. **账号是用户本人的**，风险由用户承担。所以**必须让用户本人做决定**：投多少、投哪些、什么时候停。
2. **首次使用必须本人手动登录**一次。不要把「已登录的浏览器 profile」当礼物送人——那里面是别人的 Cookie 和会话，属于**个人身份凭证**，既不合法也不安全。
3. **不要把账号交给自动化全程托管**。用户不在场就别跑。
4. **平台规则以官方最新为准**。这份文件写的是实测经验，不是平台条款；条款可能变，用之前自己看一眼。

## 五、数据隐私（分享给别人时最容易出事的地方）

必须从分发包里剔除：

- ❌ 发送方的**简历全文**、真实姓名、电话、邮箱
- ❌ 发送方的**账号 / Cookie / profile 目录**
- ❌ 发送方的**会话记录、已投清单**（这是个人求职数据）
- ❌ 任何**目标公司 HR 的个人信息**（姓名/联系方式）

留在包里的只能有：**方法、规则、脚本、配置模板**。

## 六、人工确认点（这些动作必须停下来问）

| 动作 | 为什么必须问 |
|---|---|
| 首次使用 | 用户要确认流程、确认投递口径 |
| 每次放量前（从 3–5 个扩到 50 个） | 用户要确认小样结果 |
| **发消息 / 投递** | **不可撤回** |
| 任何超出用户已授权范围的岗位类型 | 用户的口径可能变 |
| 出现验证码/异常提示 | 可能要换路线或暂停 |

> **原则**：**不可撤回的动作，永远先确认。** 对内（读、整理、归档）可以大胆；对外（发出去的东西）必须收着。

## 七、出问题时的处置

| 症状 | 处置 |
|---|---|
| 弹验证码 | **立即停止**，不要重试；告知用户，换路线或改手动 |
| 提示「操作过于频繁」 | 停止 ≥ 10 分钟，降低 `max_per_session` |
| 账号被限制 | 立即停止全部自动化，告知用户走官方申诉渠道 |
| 「已送达」但对方没收到 | 刷新消息页重新核对；不要重复发送（会造成骚扰） |
