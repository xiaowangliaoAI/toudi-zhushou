# 匹配判定标准 & 红线

> 这是整套东西里**最值钱的一层**——它不依赖任何机器，换谁、换哪个平台都能用。
> 判定必须**同时指向两处证据**：JD 的原文 + 简历的原文。指不出来的，就是没依据。

> ⚠️ **先读这段：这份文件的「骨架通用、内容是示例」**
>
> **通用的（照抄）**：判定顺序 —— **先硬门槛（一票否决）→ 再看岗位实质 → 最后才分匹配度**。
> 这三步换任何岗位、任何行业都成立，**它就是这套东西的骨架**。
>
> **示例性的（要换成你的）**：下面每一张表里**填的具体条目**，都是拿**招聘岗**举的例子
> （因为那是作者实际投过、跑通过的岗位）。两个东西要换：
>
> 1. **硬门槛的条目** → 换成你那行的门槛（证书 / 语言 / 学历 / 年限 / 特定背景 / 管理规模 / 地域）；
> 2. **「岗位实质」的危险信号** → 换成你这行的「挂羊头卖狗肉」形态。
>
> **为什么值得费这个劲**：骨架决定了你不会把额度浪费在「注定进不去」和「根本不是这回事」的岗位上。
> 那两类占了投递总量的很大一块，而且**光看标题永远看不出来**。

## 一、三条判据（每次投票前逐条过）

判定顺序不能乱：**先硬门槛，再岗位实质，最后匹配度**。

### 第 0 步 · 硬门槛（一票否决，先过这个，省时间）

JD 里写死、而简历里**没有依据**的任一条件 → **直接跳过，不投**：

| 门槛类型 | 典型表述 | 处理 |
|---|---|---|
| 语言等级 | 「英语可作为工作语言」「能流利英文电话面试」「日语 N2」 | 简历无佐证 → 跳 |
| 执业/资格证 | 「持证」「必须有人力资源管理师证」 | 简历无 → 跳 |
| 第一学历 | 「第一学历 211/985 及以上」「统招本科」 | 不符 → 跳 |
| 年龄区间 | 「27 周岁以内」「35 岁以下」 | 不符 → 跳 |
| 特定行业年限 | 「3 年以上跨境电商招聘经验」 | 无 → 跳 |
| 管理规模 | 「带 5 人以上团队」「团队负责人」 | 无 → 跳 |
| 硬性地域/驻场 | 「必须常驻XX」「需长期出差海外」 | 无 → 跳 |

> **原则**：硬门槛是「能不能进面试池」的物理条件，不是「够不够优秀」。够优秀也过不了硬门槛，投了就是浪费一次额度。

### 第 1 步 · 岗位实质（标题不算数）

**通用原则：标题写的是一个岗，职责可能是另一个岗。** 逐条读职责，对不上的跳过。

判别口诀 —— **看它赚谁的钱**：

- 招的人去干「**你将来要做的那件事**」→ 是本职岗；
- 招的人去干「**把你的东西卖给别人**」「**拉别人的客户/代理/学员**」→ 是销售岗，只是标题蹭了个名。

#### 示例：招聘岗的「实质不对」长什么样

| 危险信号（标题像招聘岗，实质不是） | 实质 | 处理 |
|---|---|---|
| 职责是**供应商开发 / 译员资源拓展 / 资源池孵化** | 采购 / BD | 跳过 |
| 职责是**房产销售招募 / 代理招募**，提成型，要行业经验 | 销售招募 | 跳过 |
| 职责是**培训招生 / 学员咨询转化** | 招转培（销售） | 跳过 |
| 职责是**纯 BP / 纯员工关系 / 纯薪酬绩效**，招聘只是附带 | 非招聘岗 | 跳过 |
| 职责是**猎头 BD**，按回款提成、要求自带客户资源 | 猎头销售 | 跳过 |
| 要求**自有客户资源 / 自带渠道资源** | 销售性质 | 跳过 |
| 明确标注 **【校招】/【2027 届】/ 面向在校生** | 校招岗 | 跳过（除非本人是应届） |

#### 换成你的岗位怎么填

同一张表，换一行就是另一回事 —— 骨架一样，条目全换：

| 你的目标岗 | 该去找什么「实质不对」的信号 |
|---|---|
| 运营 | 挂着「运营」实则**纯客服 / 内容搬运 / 刷单冲量** |
| 设计 | 挂着「设计师」实则**素材套版 / 电商主图流水线**（不产出原创方案） |
| 产品 | 挂着「产品经理」实则**纯需求文档誊写 / 项目跟单**（不碰决策） |
| 开发 | 挂着「工程师」实则**驻场外包长期外派**、或**低代码拖拽岗**（与简历技术栈不重合） |
| 管培生 | 挂着「管培」实则**一线地推 / 门店轮岗无归期** |
| 财务 | 挂着「财务」实则**纯开票 / 出纳兼行政** |

> 填这张表的**唯一要求**：条目必须来自**你真的踩过或真的见过**的形态。
> 编出来的危险信号会让你误杀好岗位。

### 第 2 步 · 匹配度（高/中/低三档）

**通用骨架就看一件事：JD 的核心工作里，有几件是你简历上真做过的。**

- **大部分都是** → 🟢 高
- **核心对得上，但有一两项没做过** → 🟡 中（**投，但招呼语只打做过的部分**）
- **核心对不上 / 硬门槛已挂** → 🔴 低

下表的**档位判定逻辑是通用的**，但**条目写的是招聘岗**——换成你的岗位时，
把「招聘全流程执行、简历筛选、候选人沟通、渠道维护、数据跟进」换成**你这行的核心动作**即可：

| 档位 | 特征（招聘岗示例） | 动作 |
|---|---|---|
| 🟢 **高** | JD 核心工作**大部分**是这几件：招聘全流程执行、简历筛选/开源、候选人沟通与面试邀约、渠道维护、招聘数据跟进。且经验要求不超过本人年限、学历不限、非管理岗 | **优先投** |
| 🟡 **中** | 核心是招聘执行，但 JD 里有**一两项本人没做过的**（如特定行业深耕、校招批量、蓝领招聘、纯猎头） | **可以投**，但招呼语**只打做过的部分，不碰没做过的** |
| 🔴 **低** | 见第 1 步的危险信号，或要求 8 年以上全模块经验、明确要求甲方 in-house 大厂背景 | **跳过** |

## 二、明确不投的岗位类型（起始默认值，写进 config）

下列类型建议直接进 `config.exclude_role_types`：

- 招聘经理 / 人力资源经理 / HRBP 负责人 / 人力资源总监 / 招聘负责人（**管理岗**）
- 高级猎头顾问 / 纯销售猎头（高底薪高业绩压力、按回款）
- 房产销售招募 / 代理招募 / 供应商开发 / 译员资源拓展（**非招聘实质**）
- 校招岗（非应届身份）

## 三、未发原因分类法（收尾必填，便于复盘）

每次跳过都必须归到一个类里，**不许写「不合适」这种废话**：

| 代码 | 含义 | 例 |
|---|---|---|
| `GATE-LANG` | 语言硬门槛 | 要求英语工作语言 |
| `GATE-EDU` | 学历/年龄硬门槛 | 第一学历 211、27 岁以内 |
| `SUBSTANCE` | 岗位实质不符 | 实为译员资源拓展/房产销售招募 |
| `DUTY-MIX` | 职责掺混 | 50% 招聘 + 50% 客服 BP |
| `SENIORITY` | 职级过高 | 招聘负责人/HRD |
| `INDUSTRY` | 行业不重合 | 硬性要求跨境电商招聘经验 |
| `CAMPUS` | 校招岗 | 面向在校/应届 |
| `MANAGEMENT` | 管理规模超标 | 带 5 人以上团队 |

> 每轮结束统计各代码条数，比「投了多少」更有信息量——它告诉你**哪个条件最卡你**。

## 四、判定的证据纪律

1. **每条判定写出证据**：`[公司] → 判定=跳 → 代码=GATE-LANG → 依据=JD原文「英语可作为工作语言」`。
2. **不许放宽硬门槛**：「虽然写着 211 但也许可以试试」——这种心态是浪费额度。硬门槛写死了就是写死了。
3. **不许收紧以凑安全**：JD 没写的条件不许自己加上去（比如 JD 没要求管理经验，不能因为「感觉他们想要强的」就跳过）。
4. **边界情形**（JD 含糊、只写了职责没写要求）：判**中档**，投，但招呼语只打确定做过的部分。
5. **同一条 JD 反复出现**：说明是长期挂岗或已招到人未下架，**降一档**处理。

## 五、示例（占位人物，勿照抄）

> 下面用「某求职者」演示判定长什么样。**换成自己的时候，证据要改成自己简历里的原文。**

| JD 摘要 | 判定 | 代码 | 依据 |
|---|---|---|---|
| 「负责目标岗位全流程、渠道维护、数据跟进，要求 3 年经验」 | 🟢 高 | — | JD 核心要求均能在简历中找到对应经历；经验要求低于本人年限 |
| 「负责译员资源池建设与供应商议价」 | 🔴 低 | `SUBSTANCE` | 职责实质是供应商开发，非员工招聘 |
| 「要求英语可作为工作语言，负责海外招聘」 | 🔴 低 | `GATE-LANG` | JD 把语言门槛写死，简历中无对应佐证 |
| 「50% 招聘 + 50% 非招聘职能（如客服团队 BP）」 | 🔴 低 | `DUTY-MIX` | 一半职责不属于目标方向 |
| 「限定第一学历层次与年龄区间」 | 🔴 低 | `GATE-EDU` | 硬门槛与本人条件不符 |

## 六、和别的层怎么衔接

- 判定**结果**写进收尾清单（已发 / 未发+原因）。
- 判定的**依据**必须能在对话里复述出来（用户会追问「这家为什么跳」）。
- 判定规则本身如果有更新 → 改**这份文件**，不要改脚本。
